# Module 7 — Capstone part I: build a feature

Apply the request-to-requirements, specification, task-planning, test, and incremental-implementation workflow to a larger feature in the Task API. Choose one feature track, work in a dedicated Git branch, and prepare a focused vertical slice for review.

## Materials

- `participant-guide.md` — project setup, track selection, implementation sequence, and review checkpoint.
- `feature-catalog.md` — three substantial feature choices and one combined advanced path.
- `issue-briefs/` — trainer-prepared GitHub Issue text for each choice.
- `prompts.md` — prompts for refinement, planning, implementation, and review.
- `trainer-notes.md` — hidden clarification cards, reference scope, and facilitation guidance.
- `target-overlays/skill/` — reusable capstone vertical-slice Skill to **ADD** alongside existing Skills.
- `target-overlays/templates/` — capstone requirements, spec, task, and handoff templates to **ADD** using the selected track name.

## Project progression

The Task API now has task creation/listing, tests, priority, and a planning workflow. Capstone options add meaningful behavior across multiple routes or data relationships: deadline tracking and filtering, labels and filtered views, or dependency-aware completion. Teams may select one feature for a manageable capstone, or combine deadline and label tracks when time and review capacity allow. Dependency-aware completion is the advanced alternative because it introduces cross-task validation and state transitions.

Use the reviewed Jira story as the capstone work item and the Miro board as product/design evidence. Search for overlapping work through the connected tracker integration; if the GitHub MCP is available, use it for repository context as well. Reuse prior test, implementation, requirements, and context Hooks/Skills. Module 9 carries the approved story set through sequential implementation and pushes.
